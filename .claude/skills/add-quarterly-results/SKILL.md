# إضافة النتائج الربعية لقطاع

تواصل مع المستخدم بالعربية دائمًا.

تستخدم كل صفحات القطاعات (ما عدا البنوك) نفس البنود التسعة، وتشترك في:
- `dist/quarterly-periods.mjs`: حساب الفترات والجدول (الربع، والمتتالية، و6 و9 أشهر).
- `dist/sector-results-page.mjs`: منطق الصفحة. يضيف شريط الفترة تلقائيًا إذا وجد `dist/<slug>-quarterly-financials.json`.
- `dist/quarterly-periods.css`: تنسيق الشريط والجداول.

صفحة التجزئة (`retail`) هي المرجع الذي تُقارن به أي صفحة جديدة.

## المدخلات
- **مسار ملف Excel**: إن لم يعطه المستخدم، ابحث في `/Users/ahmadaghnj/argaam/` عن ملف باسم القطاع، ثم اسأل المستخدم إن لم تجد.
- **القطاع**: حوّل اسمه إلى `slug` صفحته. الـ slug هو اسم الملف `dist/<slug>.html`، مثل retail وcement وfood وhotels-tourism وinformation-technology وbusiness-services. لمعرفة القطاع المقصود افتح `dist/<slug>-financials.json` واقرأ حقل `sector`.
- **البنوك** (`banks`) لها بنود مختلفة ولا تعمل بهذه الطريقة. أخبر المستخدم بذلك بدل المحاولة.

## الخطوات
1. **فرع:** إن كنت على `main` فاسأل المستخدم عن الفرع (أداة propose_branch) قبل أي تعديل.
2. **الاستيراد:**
   ```bash
   python3 scripts/import-quarterly-workbook.py <slug> "<مسار ملف Excel>"
   ```
   ينسخ الملف إلى `argaam_<slug>_quarterly.xlsx` ويكتب `dist/<slug>-quarterly-financials.json`. إن طبع «خطأ: …» فأصلح السبب أو اشرحه للمستخدم بالعربية. أسباب الخطأ المعتادة: ورقة لا تطابق شركة في الملف السنوي، أو عناوين لا تبدأ بـ«الربع …» في الصف الثاني.
   - انقل للمستخدم ما يطبعه السكربت عن «شركات بلا بيانات ربعية» و«فروق بين مجموع الأرباع والسنوي». هذه الفروق لا تمنع الإضافة، فالعرض السنوي يبقى من الملف السنوي.
   - تحقق بنفسك من شركة واحدة على الأقل: مجموع Q1 إلى Q4 لسنة كاملة يساوي الرقم السنوي في `dist/<slug>-financials.json`. إذا كان Q4 يساوي السنة كاملة، فالملف خاطئ: أوقف العمل وأخبر المستخدم.
3. **ربط الصفحة** (مرة واحدة لكل قطاع، ولا ضرر من إعادته):
   ```bash
   python3 scripts/enable-quarterly-page.py <slug>
   ```
   يعيد كتابة `dist/<slug>.js` ليستدعي `initSectorResultsPage`، ويضيف رابط `quarterly-periods.css` إلى `dist/<slug>.html`، ويحدّث أرقام الإصدار حتى لا يعرض المتصفح نسخة قديمة. عند **تحديث بيانات** قطاع مربوط من قبل، أعد تشغيله ليتغير رقم إصدار البيانات.
4. **الاختبارات:**
   ```bash
   node --test scripts/*.test.mjs tests/*.test.mjs
   ```
   هي نفس الاختبارات التي يشغّلها النشر، وتفحص ضمن ما تفحص كل ملفات `*-quarterly-financials.json`.
5. **المعاينة في المتصفح:** شغّل خادم `dist` المحلي، مثلًا `python3 -m http.server 8765 --directory dist`، ثم افتح `<slug>.html?symbol=<رمز>&period=q&q=3` وتحقق من:
   - شريط الفترة ظاهر، وعناوين الأعمدة بصيغة `Q3 2026`.
   - أوضاع ربع، ومتتالية، و6 أشهر، و9 أشهر، وسنوي كلها تعمل، والجدول بعرض الجدول السنوي («متتالية» وحده أعرض ويتمرر أفقيًا).
   - بطاقات «أبرز الأرقام» تقول مثلًا «عن Q3 2025»، ولا أخطاء في الـ console.
   - رقم واحد على الأقل يطابق ملف Excel.
6. **الرفع:**
   - اعمل commit برسالة إنجليزية واضحة، وأضف الملفات بأسمائها فقط: `argaam_<slug>_quarterly.xlsx` و`dist/<slug>-quarterly-financials.json` و`dist/<slug>.js` و`dist/<slug>.html`. لا تضف `.claude/launch.json` ولا ملفات غير متتبعة لم تنشئها.
   - ادفع الفرع، واسأل المستخدم قبل الدمج في `main`، فالموقع ينشر من `main` تلقائيًا عبر GitHub Actions.
   - بعد الدمج انتظر انتهاء النشر (`gh run watch`)، وافتح الصفحة على `https://portalnode.github.io/saudi-sectors/<slug>.html` للتأكد.

## عدة قطاعات معًا
نفّذ الخطوتين 2 و3 لكل قطاع، ثم شغّل الاختبارات والمعاينة مرة واحدة، واجمعها كلها في commit واحد أو commit لكل قطاع.

## ملاحظات
- لا تعدّل `quarterly-periods.mjs` أو `sector-results-page.mjs` لقطاع واحد، لأن أي تغيير فيهما يصل إلى كل الصفحات. إن احتجت تغييرًا فيهما، فحدّث رقم `SHARED_VERSION` في `scripts/enable-quarterly-page.py` ورقم الإصدار في سطر الاستيراد داخل `sector-results-page.mjs`، ثم أعد تشغيل الربط لكل القطاعات المربوطة. تجد القطاعات المربوطة بالأمر: `ls dist/*-quarterly-financials.json`.
